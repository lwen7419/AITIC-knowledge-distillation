# AITIC Knowledge Distillation Pipeline

## Project Goal
End-to-end automated knowledge distillation and agent generation pipeline. Converts academic textbooks (text, charts, formulas) into a locally-running vertical-domain agent on consumer hardware. "Distillation" here means structured knowledge extraction and lightweight packaging — not model weight distillation.

## File Structure
```
src/
  environment.py                    — model, embeddings, vector store setup (import this, don't re-instantiate elsewhere)
  Indexing.py                       — load PDF → heading-based semantic chunking → store in ChromaDB
  heading_based_semantic_chunker.py — custom chunker; splits on heading hierarchy and paragraph boundaries
  RAG_chain.py                      — retrieval + generation using LangChain chain approach (middleware, not agent+tool)
  testOllama.py                     — sanity check that Ollama is running and models are available

eval/
  ground_truth.py                   — test queries + reference answers per subject
  run_eval.py                       — measures Hit@5, hallucination rate, token efficiency, throughput
  results/                          — one JSON per ablation condition

chroma_langchain_db/                — local ChromaDB vector store (gitignored, generated by Indexing.py)
```

## Key Technical Decisions (do not change without discussion)
- **Embeddings**: `nomic-embed-text` via Ollama — local inference, no API key, strong on technical text
- **LLM**: `qwen3-vl-8b` via Ollama — required by project brief, multimodal capable
- **Chunking**: custom heading-based semantic chunker (`heading_based_semantic_chunker.py`), not LangChain's built-in `SemanticChunker` — preserves document structure for academic PDFs
- **RAG pattern**: chain approach via `@dynamic_prompt` middleware, not agent+tool — single LLM call per query, lower latency
- **Vector store**: ChromaDB with local persistence at `./chroma_langchain_db`
- **All inference runs locally via Ollama** — no external API calls, data never leaves the machine

## Architecture
```
PDF input
  → PyPDFLoader (environment.py)
  → heading_based_semantic_chunker (heading_based_semantic_chunker.py)
  → Document objects with metadata: {section, chunk_type, paragraph_index, page, source}
  → ChromaDB via nomic-embed-text embeddings (Indexing.py)

Query input
  → @dynamic_prompt middleware intercepts request
  → similarity_search against ChromaDB
  → context injected into system message
  → qwen3-vl-8b generates answer with citation grounding (RAG_chain.py)
```

## Metrics Targets (from project brief)
- **Hit@5 ≥ 85%** — correct answer appears in top 5 retrieved chunks
- **Hallucination rate ≤ 15%** — answers generated without citation grounding
- **Token efficiency ≤ 60% of baseline** — total tokens (prompt + retrieved chunks + output) vs. standard LangChain + Qwen-8B-Instruct RAG
- **Throughput ≥ 15 pages/minute** — end-to-end processing speed including text and images

All metrics must hold across 3 distinct subjects (e.g. CS, clinical medicine, law).

## Baseline for Comparison
Standard LangChain + RecursiveCharacterTextSplitter + Qwen-8B-Instruct RAG.
Baseline implementation lives in `eval/` — do not mix into `src/`.

## Ablation Conditions (eval/results/)
Each ablation saves a separate JSON. Conditions to test:
- Full pipeline (default)
- Heading-based chunking OFF → RecursiveCharacterTextSplitter
- Citation grounding OFF
- Q4 quantization instead of default
- Multimodal parsing OFF → plain text only

## Coding Conventions
- Always add comments explaining *why*, not just *what*
- Spread dicts instead of re-listing fields: `{**doc.metadata, **chunk}` not `{"page": chunk["page"], ...}`
- All model/embeddings/vector store instantiation lives in `environment.py` — import from there, never re-instantiate in other files
- `environment.py` has no `if __name__ == "__main__"` guard — it is meant to be imported and its top-level code runs on import by design
- Keep `src/` (pipeline) and `eval/` (benchmarking) strictly separate

## Environment
- macOS, Apple Silicon, Anaconda base environment
- Ollama running locally at localhost:11434
- Models must be pulled before running: `ollama pull qwen3-vl:8b` and `ollama pull nomic-embed-text`
- VS Code, Python via Anaconda

## Running the Pipeline
```bash
# 1. Make sure Ollama is running
ollama serve

# 2. Index documents
python src/Indexing.py

# 3. Run RAG chain
python src/RAG_chain.py

# 4. Run evaluation
python eval/run_eval.py
```
